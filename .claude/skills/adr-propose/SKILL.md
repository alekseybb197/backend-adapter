# Предложение архитектурного решения

Ты нашёл изменение, которое по правилам проекта нельзя реализовать без
решения автора. Твоя задача — оформить его, а не реализовать.

1. Определи следующий свободный номер: наибольший `NNN` среди
   `docs/adr/[0-9][0-9][0-9]-*.md` плюс один.
2. Создай `docs/adr/NNN-краткое-имя.md` по `docs/adr/TEMPLATE.md`:
   - статус `Предложено (<сегодняшняя дата>)`;
   - «Связано» — действующие ADR, которые решение уточняет или заменяет;
   - «Контекст» — только факты со ссылками на код; гипотезы помечать явно;
   - «Решение» — конкретно (модули, функции, переменные, форматы);
   - «Рассмотренные альтернативы» — минимум одна реальная, включая «не менять»;
   - «Оценка реализации» — затронутые файлы, объём, риски.
3. Добавь строку в таблицу «Предложения» `docs/adr/README.md`.
4. Прогони `pytest tests/test_adr_catalog.py`.
5. Остановись. Код по предложению не писать. Сообщи пользователю номер ADR,
   суть в двух предложениях и что нужно от него (решение «Принято» /
   «Отклонено» или ответ на вопрос).

Если задача пользователя может быть выполнена без этого решения (обходной
путь в рамках действующих ADR) — предложи этот путь в отчёте отдельно.

Описание от пользователя или из контекста задачи: $ARGUMENTS
