# ADR-037: Модель сессии из `/model` выводится из истории, которую присылает агент

| Поле | Значение |
|---|---|
| Статус | Предложено (2026-10-11); уточняет ADR-013, ADR-021 |
| Тип решения | proposal |
| Повод | ответ автора на вопрос 23: связка «сессия — модель» должна поддерживаться агентом |

## Контекст

Сейчас (`server.py`, ветка `inp_fmt == "responses"`):

1. Последнее пользовательское сообщение `/model <имя>` перехватывается,
   имя сохраняется в `session_settings._OVERRIDES` (память процесса),
   клиенту отдаётся синтетический ответ ``Model switched to `<имя>`.``,
   бэкенд не вызывается.
2. Последующие запросы сессии получают `model = <имя>` из памяти.

Проблемы:

- **Рестарт адаптера** теряет переопределение; Codex продолжает слать модель
  из своего конфига, и сессия молча переходит на другую модель.
- **Имя не проверяется при переключении:** ответ «Model switched to
  `xyz`» отдаётся и для несуществующей модели; ошибка strict-проверки придёт
  только на следующем запросе, без связи с командой.

## Ключевое наблюдение

При `store:false` (ADR-013) клиент в **каждом** запросе присылает всю
историю. В ней уже есть и команда пользователя, и ответ адаптера. Значит,
привязка «сессия → модель» действительно хранится у агента — нужно лишь
читать её из истории, а не из памяти.

## Решение

**Источник истины — пара «команда пользователя + подтверждение адаптера»** в
`input`, последняя по порядку:

```python
_SWITCH_ACK_RE = re.compile(r"^Model switched to `(\S+)`\.$")


def model_from_history(input_items: list) -> str | None:
    """Последнее подтверждённое переключение модели в истории Responses.

    Засчитывается только ПАРА: сообщение role=user с точным текстом
    "/model <имя>", за которым СЛЕДУЮЩИМ элементом идёт сообщение
    role=assistant с точным текстом ack адаптера для того же имени.
    """
    result = None
    for prev, cur in zip(input_items, input_items[1:]):
        if not (isinstance(prev, dict) and isinstance(cur, dict)):
            continue
        if prev.get("role") != "user" or cur.get("role") != "assistant":
            continue
        cmd = _MODEL_SWITCH_RE.match((_extract_responses_input_text(prev) or "").strip())
        ack = _SWITCH_ACK_RE.match((_extract_responses_message_text(cur.get("content")) or "").strip())
        if cmd and ack and cmd.group(1) == ack.group(1):
            result = cmd.group(1)
    return result
```

Порядок определения модели запроса:

1. текущая команда `/model x` → проверка имени (см. ниже) → ack, бэкенд не
   вызывается (как сейчас);
2. иначе `model_from_history(input)`;
3. иначе переопределение из памяти (страховка на случай, если клиент
   сжал историю и пара исчезла, а адаптер не перезапускался);
4. иначе модель из тела запроса.

**Проверка имени при переключении:** при `ADAPTER_STRICT_MODELS=1` и имени
не из списка — ответ ``Model `x` is not available. Allowed: …`` (текст **не**
совпадает с `_SWITCH_ACK_RE`), переопределение не меняется. Благодаря этому
отклонённая команда никогда не засчитается при чтении истории.

## Безопасность

- **Почему пара, а не одно подтверждение.** Текст ответа модели
  контролируется моделью, а модель может быть подведена prompt injection
  (например, через вывод инструмента) к ответу с точным текстом
  ``Model switched to `x`.``. Сообщения с `role=user` модель создать не
  может. Требование пары «user-команда → ack» исключает подмену модели через
  injection.
- Даже при подмене выбор ограничен моделями из strict-списка — подмена
  меняет модель, но не бэкенд и не учётные данные.
- Точное совпадение всего сообщения: `/model x` внутри обычного текста
  пользователя командой не считается (как и сейчас: `^…$`).

## Следствия

- Переключение переживает рестарт адаптера без `state.yaml` и без TTL.
- Если Codex сжимает историю и пара исчезает, после рестарта модель
  вернётся к конфигу клиента — остаточный случай; его стоит записать в
  `docs/codex.md`.
- **Допущение, которое нужно проверить** до реализации: Codex возвращает
  синтетический ответ адаптера в `input` последующих запросов как
  `{type: "message", role: "assistant", …}`. Проверяется по `*.parts`-дампу
  (`OPENAI_BODY`/`BODY`) реальной сессии с `/model`.
