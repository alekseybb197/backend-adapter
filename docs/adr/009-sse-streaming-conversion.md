# ADR-009: Стриминг — конверсия SSE на лету; ретрай только до первого байта

| Поле | Значение |
|---|---|
| Статус | Действует (v0.4.0); дословный релей добавлен в v0.9.0 |
| Тип решения | deliberate (записано) |
| Уверенность | high |
| Источник рационала | changelog v0.4.0 (восстановлен из `becdabd9:changelog.md`); журнал ADR 2026-09-09 |

## Контекст

До v0.4.0 адаптер принудительно слал бэкенду `stream: false` и ждал ответ
целиком. Пока модель думала (десятки секунд), клиент не получал ни байта,
рвал соединение по своему таймауту, а адаптер получал `BrokenPipeError` при
записи уже готового ответа.

## Решение

- Флаг `stream` клиента пробрасывается бэкенду как есть.
- `stream_openai_to_anthropic()` читает SSE бэкенда построчно и сразу пишет
  Anthropic-события (`message_start` → `content_block_*` → `message_delta` →
  `message_stop`).
- **Ретрай возможен только до отправки первого байта клиенту** (этап
  `urlopen` и заголовков). После старта потока сбой сообщается SSE-событием
  `error` — второй `message_start` сломал бы протокол.
- Уход клиента (`BrokenPipe`/`ConnectionReset`) — `[CLIENT_GONE]` в лог, без
  падения.
- Для дословных маршрутов (v0.9.0) — `relay_sse`: байты бэкенда
  пересылаются без пере-фрейминга, с побочным сканом usage.
- Ошибка после старта потока — в **родном формате входа**
  (`_write_sse_error_native`).
- Аварийный выключатель `ADAPTER_STREAMING_ENABLE=0` возвращает старое
  поведение.
- Usage в стриме запрашивается через `stream_options.include_usage`
  (`ADAPTER_STREAM_INCLUDE_USAGE`, v0.5.2); если бэкенд его не прислал —
  оценка `chars // 4`, явно помеченная как оценочная.

## Рассмотренные альтернативы

- Буферизовать ответ целиком (старое поведение). Отвергнуто: таймауты
  клиента.
- Ретрай в середине потока. Отвергнут: нарушает протокол клиента.

## Следствия

- Все поздние механизмы повтора (адаптивный подъём `max_tokens`, ADR-010)
  обязаны учитывать границу «поток начат» — отсюда страховки `not started` /
  `not pt_started` / `not r_started` в `server.py`.
- Обрыв mid-stream с v0.9.7 фиксируется в `.err` с `final_status=200`
  (ADR-019).

## Доказательства
