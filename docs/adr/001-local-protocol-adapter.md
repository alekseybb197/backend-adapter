# ADR-001: Локальный прокси-адаптер протоколов между агентом и бэкендом

| Поле | Значение |
|---|---|
| Статус | Принято (с v0.1, MVP `d1ad213`, 2026-08-20) |
| Тип решения | deliberate (по признакам) — мотив записан, альтернативы нет |
| Уверенность | high — что решено; medium — почему именно так |
| Источник рационала | `README.md` «Проблемы, которые решает адаптер», `CLAUDE.md` «Цели проекта»; реконструкция |

## Контекст

Агенты с Anthropic-совместимым API ([CC], позже QwenCode и Codex CLI)
должны работать через корпоративный LLM-бэкенд, который реализует
[OI]-совместимый `/v1/chat/completions`, но некорректно обрабатывает
протокол Anthropic Messages. Зафиксированы четыре конкретных дефекта:

1. бэкенд переносит system-сообщения в конец диалога;
2. формат запроса/ответа не совпадает (сообщения, инструменты, tool choice);
3. модели Qwen нужно использовать через клиентов, которые их не знают;
4. модели Qwen иногда возвращают вызовы инструментов текстом в XML-подобных
   тегах вместо нативных `tool_calls`.

Бэкенд находится вне контроля автора (в `docs/architecture.md` §3 как пример
бэкенда указан корпоративный LLM-сервис).

## Решение

Отдельный HTTP-процесс на машине пользователя (по умолчанию
`127.0.0.1:9999`), который клиент считает Anthropic API
(`ANTHROPIC_BASE_URL`). Адаптер нормализует и конвертирует запросы, ходит
в бэкенд по [OI]-протоколу и собирает ответ обратно в формат клиента.

## Рассмотренные альтернативы

Не записаны. Правдоподобные варианты (гипотеза, требует подтверждения):

- исправление бэкенда — вне контроля автора;
- готовый прокси-шлюз (LiteLLM и т. п.) — в документации LiteLLM фигурирует
  только как **один из бэкендов** за адаптером, а не как замена ему;
- патч или обёртка клиента — клиенты закрытые/внешние.

## Следствия

- Клиент и бэкенд не меняются; вся несовместимость локализована в одном
  процессе.
- Адаптер оказывается на критическом пути каждого запроса агента: его
  надёжность и наблюдаемость становятся приоритетами (см. ADR-009, ADR-010,
  ADR-018, ADR-019).
- Со временем адаптер вырос из «фикса одного бэкенда» в маршрутизатор
  нескольких входных протоколов (ADR-011): формулировка назначения в
  `__comment__` — «backend router and endpoint adapter».
