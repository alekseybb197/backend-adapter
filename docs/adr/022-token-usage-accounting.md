# ADR-022: Учёт расхода в токенах из usage бэкенда; учёт не влияет на запрос

| Поле | Значение |
|---|---|
| Статус | Принято (v0.8.4); тарифы — v0.8.6 |
| Тип решения | deliberate (записано) |
| Уверенность | high |
| Источник рационала | журнал ADR 2026-09-06 (×3), 2026-09-08 «Колонка Cost» |

## Контекст

Нужно видеть, какие модели агент реально вызывает и сколько это стоит, по
каждому провайдеру.

## Решение

- Таблица «Models in use» (`model_usage.py`): строка на клиентское имя модели
  (до маппинга): вызовы, `input_tokens`, `output_tokens`, первое обращение.
- Токены берутся **только из `usage` ответов бэкенда** (не-стрим — тело;
  стрим — последний чанк с usage). Ответ без usage даёт 0. Оценка `chars/4`
  остаётся только в trace и в учёт не попадает.
- Фиксация **один раз** в `finally` `do_POST` — на любом исходе.
- **Учёт не может уронить запрос:** все исключения ловятся внутри; сетевых
  вызовов при учёте нет (с v0.9.9).
- Стоимость считается на лету из токенов и `ADAPTER_MODELS_TARIFFS`
  (YAML: цена за `price_per` токенов, валюта); в файл не пишется.
- Персистентность — `var/model-usage.yaml` с версией формата (ADR-025).

## Рассмотренные альтернативы

- **Учёт в байтах тел обмена** (v0.8.4, первая реализация). Заменён в тот же
  день: «диагностика в ответах приходит в токенах — байты не отражают
  фактический расход». Миграция файла v1 → v2 сохраняет вызовы, байтовые поля
  отбрасывает.

## Следствия

- Бэкенд без usage выглядит бесплатным (0 токенов, «—» в Cost).
- В стриме usage зависит от `stream_options.include_usage` (ADR-009).
- Повторные попытки и подъёмы `max_tokens` (ADR-010) учитываются только по
  успешному ответу, неудачные попытки в расход не попадают, хотя провайдер мог
  их тарифицировать.
