# ADR-003: HTTP/1.0 и `Connection: close` вместо keep-alive

| Поле | Значение |
|---|---|
| Статус | Принято (v0.4.0); признанный технический долг |
| Тип решения | deliberate (записано) |
| Уверенность | high |
| Источник рационала | changelog v0.4.0 «HTTP/1.0 keep-alive lie fix» (свёрнут в v0.9.11, восстановлен из `becdabd9:changelog.md`); docstring `_start_sse` в `server.py` |

## Контекст

`BaseHTTPRequestHandler.protocol_version` по умолчанию `HTTP/1.0`: сервер
закрывает соединение после каждого ответа. При этом `_start_sse()` отправлял
`Connection: keep-alive`. Клиент клал сокет в пул, следующий запрос уходил в
уже закрытое соединение и получал `ECONNRESET` — в терминале агента это
выглядело как `API Error: The operation timed out` после успешного ответа.

## Решение

Честно сообщать клиенту, что соединение закрывается: `_start_sse()` шлёт
`Connection: close` и выставляет `self.close_connection = True`. Протокол
остаётся HTTP/1.0. Конец SSE-потока для клиента — закрытие соединения
(используется и в passthrough-релее, ADR-009).

## Рассмотренные альтернативы

- Настоящий keep-alive: `protocol_version = "HTTP/1.1"` + chunked-фрейминг.
  Отложен: автор отметил, что это отдельная правка (changelog v0.4.0,
  примечание).

## Следствия

- Ложные таймауты устранены.
- Каждый запрос агента — новое TCP-соединение к адаптеру. Для локального
  `127.0.0.1` цена мала. Соединение адаптер → бэкенд тоже не
  переиспользуется (`urlopen` без пула): на удалённый бэкенд по TLS каждый
  ход агента платит рукопожатием.

## Доказательства

- `6d98c39` (streaming, v0.4).
- `backend_adapter/server.py`, docstring `_start_sse` («ВАЖНО про
  Connection…»), `self.send_header("Connection", "close")`.
