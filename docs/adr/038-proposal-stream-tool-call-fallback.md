# ADR-038: Распознавание текстовых `<tool_call>` в стриме

| Поле | Значение |
|---|---|
| Статус | Предложено (2026-10-11); закрывает пробел ADR-008 |
| Тип решения | proposal |
| Повод | ответ автора на вопрос 5: «это пробел; хотелось бы понять негативные последствия» |

## Последствия пробела

Когда модель Qwen в стриме отвечает вызовом инструмента текстом, а бэкенд не
переводит его в `tool_calls`:

1. [CC] получает `text_delta` с сырым `<tool_call>{"name": …}</tool_call>`
   и `stop_reason = "end_turn"` (finish_reason бэкенда — `stop`).
2. Для агента это **финальный текстовый ответ**: инструмент не вызывается,
   агентный цикл останавливается, пользователь видит в терминале XML.
3. В интерактивном режиме человек замечает и пишет «продолжай». В
   неинтерактивном (`claude -p`, CI, оркестраторы) задача **молча
   завершается как выполненная** — самый дорогой вариант, ошибки нет.
4. Это нельзя измерить: событие `tool_call_fallback` эмитится только в
   не-стрим пути, а стрим — основной режим [CC]. Частота проблемы в
   реальных сессиях сейчас неизвестна.

Насколько часто это случается, зависит от бэкенда: при правильно настроенном
парсере вызовов (vLLM `--tool-call-parser`, llama.cpp `--jinja`) теги
разбирает сервер. Пробел проявляется на бэкендах и шаблонах, которые этого
не делают.

## Решение

### Шаг 1 — измерить (дёшево, сразу)

В конце `stream_openai_to_anthropic` проверить собранный `full_text` на
`<tool_call>` и эмитить trace-событие `tool_call_text_in_stream`
(количество тегов, `finish_reason`). Даст частоту без изменения поведения.

### Шаг 2 — инкрементальный распознаватель

Текст продолжает идти клиенту сразу. Придерживается только минимальный
хвост, который может оказаться началом тега (`<`, `<to`, …), — до следующего
фрагмента. Содержимое тега копится; на `</tool_call>` JSON разбирается и
вместо текста отдаётся `tool_use`-блок. Неразбираемый или незакрытый тег
отдаётся текстом — ничего не теряется молча.

Прототип (`TextToolCallSniffer`, ~110 строк, только stdlib) проверен
тестами:

- **полный перебор разрезов** документа с вызовом на 1–3 куска (больше
  5000 вариантов) — результат идентичен;
- 2000 случайных посимвольных разбиений документа с двумя вызовами и
  ложными префиксами `<b`, `<tool_c`;
- обычный текст проходит без задержки; `<` придерживается ровно на один
  фрагмент;
- неразбираемый JSON, тег без `name`, массив вместо объекта →
  возвращаются текстом;
- незакрытый к концу потока тег → текстом в `finish()`;
- формы `{"function": {"name", "arguments": "<json-строка>"}}`;
- одинаковые вызовы получают **разные** id (uuid);
- «тег» больше 1 МиБ без закрытия → отдаётся текстом (защита памяти).

Ядро:

```python
OPEN, CLOSE = "<tool_call>", "</tool_call>"


def _partial_prefix_len(s: str, tag: str) -> int:
    """Длина самого длинного суффикса s, являющегося собственным префиксом tag."""
    for n in range(min(len(s), len(tag) - 1), 0, -1):
        if s.endswith(tag[:n]):
            return n
    return 0


class TextToolCallSniffer:
    def feed(self, piece: str) -> list[Event]: ...   # TextEvent | ToolCallEvent
    def finish(self) -> list[Event]: ...             # конец потока: всё придержанное — текстом
```

Полный код и тесты прототипа — [`proposals/038/`](proposals/038/)
(`sniffer.py`, `test_sniffer.py`; запуск: `cd docs/adr/proposals/038 &&
pytest -o addopts="" test_sniffer.py`). При реализации перенести в
`backend_adapter/streaming.py` и `tests/test_streaming.py`.

### Встраивание в `stream_openai_to_anthropic`

- Вместо прямой отправки `text_piece` — `for ev in sniffer.feed(text_piece)`:
  `TextEvent` → существующая ветка текста; `ToolCallEvent` →
  `_close_current_block()`, `content_block_start` с `tool_use`,
  `content_block_delta` с `input_json_delta` (весь JSON аргументов),
  `content_block_stop`, `_register_tool_use(...)` для причинности.
- После цикла — `sniffer.finish()`.
- Если распознан хотя бы один вызов, а `finish_reason == "stop"` —
  `stop_reason = "tool_use"`: иначе агент не выполнит вызов.
- Trace: `tool_call_fallback` с `streamed=True` — тот же сигнал
  деградации, что и в не-стрим пути.

### Попутно — не-стрим путь

`parse_tool_calls_from_text` строит id как `abs(hash(match)) % 10**10`: два
одинаковых вызова в одном ответе получают одинаковый `tool_use_id`, что
нарушает протокол Anthropic. Заменить на `uuid4`, как в стриме.

## Следствия

- Задержка видимого текста — только на длину возможного префикса тега (до
  10 символов) и только когда он встречается.
- Если модель пишет текст **о** теге `<tool_call>` с валидным JSON внутри,
  он будет исполнен как вызов. Так же сейчас ведёт себя не-стрим путь;
  риск принят в ADR-008.
