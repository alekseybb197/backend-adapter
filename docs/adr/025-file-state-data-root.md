# ADR-025: Состояние — в файлах с атомарной записью; единый корень данных `~/.ba`

| Поле | Значение |
|---|---|
| Статус | Действует; раскладка — v0.9.9 (`log/`, `var/`), v0.9.13 (дом = корень данных) |
| Тип решения | deliberate (записано) |
| Уверенность | high |
| Источник рационала | журнал ADR 2026-09-03, 2026-09-06, 2026-09-08; changelog v0.9.6, v0.9.9, v0.9.13 |

## Контекст

Адаптеру нужно хранить немного долговременного состояния: таблицу расхода
моделей, runtime-настройки `/config`, результаты опроса моделей, PID. База
данных для этого избыточна.

## Решение

- **Никакой БД.** Каждый вид состояния — отдельный файл YAML/JSON.
- **Атомарная запись:** временный файл + `os.replace` (`model_usage`,
  `state_store`, `probe_json`); пометка «грязный» снимается только после
  успешной замены.
- **Версия формата в файле** (`model-usage.yaml`: `version: 2`) с миграцией
  при загрузке; незнакомая версия или битый файл — таблица стартует пустой.
- **Корень данных** `ADAPTER_DATA_ROOT`, дефолт `~/.ba`, две подпапки с
  фиксированными ролями:
  - `log/` — всё файловое о сессиях: `session-*.log/.jsonl`, `*.parts`, `.err`;
  - `var/` — состояние: `adapter.pid`, `model-usage.yaml`, `state.yaml`,
    `<бэкенд>.models.json`.
- **Дом = корень данных** (v0.9.13): `--root` и `ADAPTER_DATA_ROOT` — один
  путь; там же `adapter.env`, `adapter.yaml`, `tariffs.yaml`. Без `--root`
  дом ищется: текущая папка → `~/.ba`.
- **`state.yaml` применяется поверх env** на старте; каждое изменение
  `/config` сразу персистится (v0.9.6). Пер-сессионные настройки не
  сохраняются (ADR-021).
- Таблица расхода сохраняется не чаще `ADAPTER_MODEL_USAGE_SAVE_INTERVAL`
  (300 с), но сразу — при создании строки, сбросе, удалении и выходе.

## История каталога данных

| Версия | Путь | Почему изменено |
|---|---|---|
| ≤ v0.6 | `ADAPTER_DEBUG_LOGFILE` (файл или каталог) | — |
| 2026-09-03 | `ADAPTER_DEBUG_LOGPATH`, дефолт `./tmp/logs` | одна переменная вместо двух |
| v0.7.2 | WEBUI-корень отдельно, `./tmp/webui` | zero-config без создания каталогов |
| v0.8.6 | снова один путь, всегда непуст | путаница «где консоль, где диск» |
| v0.9.9 | `ADAPTER_DATA_ROOT` + `log/`/`var/`, дефолт `./tmp/adapter` | каталог перестал быть только логами |
| v0.9.13 | дефолт `~/.ba`, совпадает с домом | `--root` и корень данных расходились |

## Следствия

- Дефолт до v0.9.13 зависел от текущего каталога запуска; с v0.9.13 — от
  `HOME`. Под systemd с иным `HOME` данные окажутся в неожиданном месте.
- `state.yaml` поверх env: значение, изменённое в WEBUI, переживает рестарт
  и перекрывает env (ADR-004, открытый вопрос).
- Пять переименований/перемещений каталога за месяц; старые данные при
  переименовании не мигрируются.

- `backend_adapter/config.py`: `log_dir()`, `var_dir()`.
- `backend_adapter/cli_args.py`: автопоиск дома, `setdefault`.
