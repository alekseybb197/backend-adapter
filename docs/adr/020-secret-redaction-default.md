# ADR-020: Маскирование секретов во всех наблюдательных каналах по умолчанию

| Поле | Значение |
|---|---|
| Статус | Действует (с v0.3.0; выключатель — v0.6.1); **пробелы подтверждены**, исправление — ADR-040 |
| Тип решения | deliberate (записано) |
| Уверенность | high |
| Источник рационала | `CLAUDE.md` «Принципы»; changelog v0.6.1; `docs/sanitizing.md` |

## Контекст

Логи, трейсы, дампы частей, `.err`, JSON-результаты опроса моделей содержат
заголовки авторизации, токены бэкендов и вывод инструментов агента
(`env`, файлы конфигураций).

## Решение

- `redact.py` маскирует по шаблонам: `Bearer …`, `*_KEY`, `*_TOKEN`,
  `*_SECRET`, `*_PAT` и т. п.; для JSON-структур (`probe_json`) — рекурсивно
  по ключам.
- Применяется во **всех** каналах: консоль, файлы, trace, `.err`, `var/*.json`.
- `ADAPTER_SENSITIVE_LOGGING_ENABLE=1` полностью отключает маскирование —
  для отладки формата токенов. **Сетевой трафик к бэкенду не модифицируется
  ни в каком режиме** — только логи.
- Значение читается живьём (можно переключить через `/config`).

## Рассмотренные альтернативы

- Постоянное маскирование без выключателя (до v0.6.1). Отвергнуто: отладка
  формата токена требовала правки кода.

## Следствия

- Маскирование эвристическое: секреты нестандартного вида (пароль в
  произвольном тексте, ключ без известного префикса) пройдут.
- Выключатель доступен на лету через WEBUI `/config` — тот, кто имеет доступ к
  WEBUI, может включить запись секретов (см. ADR-024).

## Подтверждённые пробелы маскирования (2026-10-11)

Проверено на реальном пути логирования (`redact_headers` → `logger._dr`):

| Вход | В консоли |
|---|---|
| `x-api-key: sk-ant-api03-AbCdEf0123456789xyz` | **без изменений** |
| `Authorization: Bearer sk-live-0123456789abcdef` | `Bearer sk-l***REDACTED***cdef` |
| `Authorization: Basic YWRtaW46aHVudGVyMg==` | **без изменений** (base64 `admin:hunter2`) |
| `ADAPTER_WEBUI_PASSWORD=hunter2secret` | **без изменений** |

- `redact_headers` смотрит только на `Authorization`; `x-api-key`,
  `api-key`, `Cookie`, `Proxy-Authorization` не маскируются.
- Шаблон имён-секретов требует подчёркивания (`API_KEY`), поэтому
  дефисная форма `x-api-key` в тексте тоже не ловится.
- Заголовки каждого входящего запроса печатаются в **безусловный**
  консольный канал (`server.py`, блок `[REQ]`). [CC] передаёт
  `ANTHROPIC_API_KEY` в `x-api-key`: если пользователь его задал, ключ
  попадает в консоль и journald. Рекомендация `docs/claude_code.md` оставлять
  `ANTHROPIC_API_KEY` пустым снижает риск, но не устраняет его.

Исправление (проверенный прототип) — [ADR-040](040-proposal-webui-auth-csrf-host.md), слой 5.

## Доказательства

- `backend_adapter/redact.py`: `_SECRET_PATTERNS`, `redact`, `redact_headers`.
- `backend_adapter/config.py`: `ADAPTER_SENSITIVE_LOGGING_ENABLE` (дефолт `0`).
- `docs/sanitizing.md`.
