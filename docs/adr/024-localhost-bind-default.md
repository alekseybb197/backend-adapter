# ADR-024: Привязка к 127.0.0.1 по умолчанию

| Поле | Значение |
|---|---|
| Статус | Принято (2026-09-03, до тега v0.8.0) |
| Тип решения | deliberate (записано) |
| Уверенность | high |
| Источник рационала | журнал ADR 2026-09-03 «Настраиваемые адреса прослушивания» |

## Контекст

Адаптер слушал все интерфейсы (`("", PROXY_PORT)` → INADDR_ANY), а WEBUI был
жёстко привязан к `127.0.0.1`. Для сетей и контейнеров нужно управлять
адресами, а «все интерфейсы» по умолчанию небезопасно: прокси подставляет
токен бэкенда, а WEBUI показывает содержимое сессий (git log, файлы,
reasoning).

## Решение

- `ADAPTER_ENDPOINT_HOST` и `ADAPTER_WEBUI_HOST`, дефолт обеих —
  `127.0.0.1`. Экспортёр использует `ADAPTER_WEBUI_HOST`.
- Идиома `os.environ.get(name, "") or "127.0.0.1"`: **пустая** переменная
  тоже даёт localhost (в bind-кортеже пустая строка означала бы все
  интерфейсы).
- `0.0.0.0` — только осознанным явным значением.

## Рассмотренные альтернативы

- Оставить INADDR_ANY (прежнее поведение адаптера). Отвергнуто как
  небезопасное по умолчанию.

## Следствия

- Это **единственная** мера контроля доступа. Ни прокси, ни WEBUI, ни
  экспортёр не проверяют аутентификацию. Любой процесс на той же машине
  (или в сети при `0.0.0.0`) может:
  - ходить в бэкенд с токеном адаптера;
  - читать полные сессии и `.err`;
  - через `/config` включить запись секретов (ADR-020) или сменить маршруты.
- В контейнере для доступа снаружи нужен `0.0.0.0`, и тогда защита целиком
  ложится на сеть.

## Доказательства

- `backend_adapter/config.py`: `ADAPTER_ENDPOINT_HOST`, `ADAPTER_WEBUI_HOST`
  (идиома с `or "127.0.0.1"` и комментарием).
- `docs/claude_code.md`: `ANTHROPIC_API_KEY` оставляется пустым —
  «авторизацию на бэкенде выполняет адаптер».

## Открытые вопросы автору
