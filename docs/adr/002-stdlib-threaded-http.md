# ADR-002: Стандартная библиотека для HTTP; модель «поток на запрос»

| Поле | Значение |
|---|---|
| Статус | Действует (с MVP `d1ad213`) |
| Тип решения | deliberate (записано) — подтверждено автором 2026-10-10 |
| Уверенность | high |
| Источник рационала | `CLAUDE.md` «Приоритеты: … минимум зависимостей»; реконструкция |

## Контекст

Адаптер — локальный инструмент разработчика, который запускается рядом с
агентом и позже распространяется одиночным бинарником (ADR-028). Нагрузка —
единицы одновременных агентов, каждый шлёт запросы последовательно.

## Решение

- HTTP-сервер — `http.server.ThreadingHTTPServer` (подкласс
  `QuietThreadingHTTPServer` в `server.py`), обработчик —
  `BaseHTTPRequestHandler`.
- HTTP-клиент к бэкенду — `urllib.request.urlopen` с общим `SSL_CTX`.
- Конкурентность — один поток ОС на входящий запрос; блокирующий ввод-вывод;
  `asyncio` не используется нигде в пакете.
- Тот же стек для WEBUI (ADR-023) и Prometheus-экспортёра.

## Рассмотренные альтернативы

Не записаны. Очевидные: `aiohttp`/`FastAPI`+`uvicorn`/`httpx`. Все добавляют
зависимости и (для async) иную модель конкурентности.

## Следствия

- Положительные: ноль сетевых зависимостей; простая отладка; стримы SSE
  пишутся прямо в `wfile` без event loop; бинарник PyInstaller остаётся
  небольшим.
- Отрицательные:
  - нет HTTP/1.1 keep-alive из коробки — см. ADR-003;
  - разделяемое состояние в глобалах модулей читается и пишется из многих
    потоков, синхронизация точечная (`_TABLE_LOCK`, `_REFRESH_LOCK`) —
    см. ADR-017;
  - длинный стрим удерживает поток на всё время ответа модели.
- Ограничение сохраняется для новых модулей: `prometheus_exporter.py` и
  `webui_ops.py` специально сделаны stdlib-only.

## Доказательства

- `d1ad213`: `import http.server`, `urllib.request`, `ssl`.
- `backend_adapter/server.py`: `class QuietThreadingHTTPServer(http.server.ThreadingHTTPServer)`,
  вызовы `urllib.request.urlopen(...)`.
- Внешние импорты пакета — только `yaml` (проверено по всем `import` в
  `backend_adapter/` и `backend-adapter.py`).

## Ответ автора (2026-10-10)

Минимальная зависимость — **изначальное требование**, а не следствие MVP.
Решение подтверждено; новые подсистемы обязаны его соблюдать.
