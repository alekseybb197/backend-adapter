# ADR-019: Безусловный канал `.err`-инцидентов

| Поле | Значение |
|---|---|
| Статус | Принято (v0.9.0); расширено в v0.9.1, v0.9.5, v0.9.7, v0.9.8 |
| Тип решения | deliberate (записано) |
| Уверенность | high |
| Источник рационала | журнал ADR 2026-09-08 «Протокол .err-инцидентов»; changelog v0.9.5, v0.9.7, v0.9.8 |

## Контекст

Файловое логирование по умолчанию выключено (ADR-018). Когда агент получает
ошибку, данных для разбора нет, а включить логи постфактум нельзя.

## Решение

При финальном ответе клиенту со статусом ≥ 400 (после всех ретраев)
адаптер **всегда** пишет блок в `session-*.err`: метаданные, полный запрос,
полное тело ошибки последней попытки. Без обрезки, вне
`ADAPTER_DEBUG_ENABLE`, с маскированием секретов по умолчанию.

Охват по версиям:

| Версия | Что добавлено |
|---|---|
| v0.9.0 | ошибки бэкенда после ретраев |
| v0.9.1 | WARN-события |
| v0.9.5 | ошибки уровня адаптера до бэкенда: disabled/reject, 400 валидации, 501 |
| v0.9.7 | отвязка от таблицы сессий; 500 при необработанном исключении; 501 неподдерживаемых методов; **обрыв потока mid-stream** (`final_status=200`) |
| v0.9.8 | WEBUI-превью `/errors/<имя>` по секциям |

Право на запись определяет распознанный входной путь
(`_req_ctx.err_eligible`), а не наличие таблицы сессий.

## Рассмотренные альтернативы

- Писать ошибки только при включённом логировании. Отвергнуто: исходная
  мотивация канала — данные при выключенных логах.
- Учитывать право через таблицу сессий (до v0.9.7). Отвергнуто: при
  `ADAPTER_SESSIONS_TABLE=0` ошибки молча выпадали.

## Следствия

- Каждая ошибка оставляет полный запрос агента на диске, даже когда
  пользователь «выключил логи». Это осознанный обмен приватности на
  разбираемость; маскируются только секреты по шаблонам.
- Канал стал механизмом обнаружения неверной маршрутизации взамен проб
  (ADR-012).
