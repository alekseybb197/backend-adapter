# ADR-011: Три входных эндпойнта и TARGET-маршрутизация по статической таблице

| Поле | Значение |
|---|---|
| Статус | Принято (v0.9.0); пересмотрено в v0.9.4, v0.9.9, v1.0.0 |
| Тип решения | deliberate (записано) |
| Уверенность | high |
| Источник рационала | журнал ADR 2026-09-09; changelog v0.9.4, v0.9.9, v1.0.0; `docs/routing.md` |

## Контекст

Изначально адаптер принимал только `POST /v1/messages`. Появились клиенты на
других протоколах: [OI]-SDK (`/v1/chat/completions`) и Codex CLI
(`/v1/responses`). Нужно было решать для каждого входа: конвертировать,
передать дословно или отказать.

## Решение (текущее, v1.0.0)

- Три входа: `/v1/messages`, `/v1/chat/completions`, `/v1/responses`
  (`routing.INPUT_PATHS`).
- На каждый вход — переменная `ADAPTER_<ВХОД>_TARGET` со значением из домена
  `messages | completions | responses | passthrough | none`:
  - значение-формат — **прямое преобразование** в этот формат, даже если он
    совпадает с входом;
  - `passthrough` — дословная передача на эндпойнт входного формата;
  - `none` — вход выключен (404).
- Решение принимает `routing.decide()` **только по значению переменной и
  статической таблице** `IMPLEMENTED_CONVERSIONS`; сети в момент решения нет.
  Нереализованная пара — 400 «conversion … is not implemented».
- Реализованные пары: `messages→completions`, `messages→messages`
  (сортировка system), `responses→completions`, `responses→responses`
  (`store:false` + `/model`), `completions→completions` (копия).
- Дефолты всех трёх входов — `completions` (v1.0.0).
- Значение можно переопределить для отдельной сессии (ADR-021) и на лету
  через `/config`.
- Невалидное значение — `[WARN]` и трактовка как `none`; старт не падает.

## Рассмотренные альтернативы и история

| Версия | Решение | Почему изменено |
|---|---|---|
| v0.9.0 | значение `auto` — выбор по кэшу проб эндпойнтов; формат = входу означал дословную передачу | — |
| v0.9.4 | `auto` удалён; добавлен `passthrough`; формат = входу теперь **конверсия** | `auto` «приемлемой логики не имело и путало»; в одном значении смешивались «целевой формат» и «режим передачи» |
| v0.9.9 | `decide` всегда оптимистичен (сняты ветки 502) | пробы эндпойнтов удалены (ADR-012) |
| v1.0.0 | дефолты `completions` у всех входов (было: `none` у двух новых) | «нулевая настройка» должна работать для всех трёх клиентов |

## Следствия

- Неверный выбор маршрута обнаруживается по факту ошибки бэкенда и попадает
  в `.err` (ADR-019), а не предсказывается.
- Breaking changes при каждом пересмотре: в v0.9.4 прежние
  `ADAPTER_COMPLETIONS_TARGET=completions` начали давать 400 (миграция —
  на `passthrough`); в v1.0.0 закрытые входы открылись (миграция — `none`
  явно).
- Дефолты продублированы в `config.py` и `routing._TARGET_DEFAULTS`
  («зеркало»): синхронизация держится на дисциплине и тестах.
- В runtime-пул `/config` TARGET сначала не входили («меняют топологию
  входов», журнал 2026-09-09), но были добавлены в v0.9.1.
