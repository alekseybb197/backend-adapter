# ADR-004: Конфигурация через переменные окружения; «нулевая настройка»

| Поле | Значение |
|---|---|
| Статус | Действует (с MVP); уточнено в v0.7.2, v0.9.11, v1.0.0 |
| Тип решения | deliberate (записано) |
| Уверенность | high |
| Источник рационала | `CLAUDE.md` «Приоритеты» и «Принципы»; журнал ADR 2026-09-04 «Zero-config» |

## Контекст

Инструмент запускается разработчиком локально, а также под systemd/launchd и
в контейнере. Настройки должны одинаково задаваться во всех трёх средах.

## Решение

- Все настройки — env-переменные с префиксом `ADAPTER_`; полный справочник —
  `docs/environment.md`.
- Минимальный запуск — путь к YAML бэкендов (`ADAPTER_BACKEND_CONFIG`) и
  env-переменная с токеном (ADR-014).
- Каждая новая возможность закрывается флагом; дефолт выбирает безопасное
  поведение («Новые возможности покрываются флагами окружения…, дефолты
  выбирают безопасное поведение»).
- Дефолты не должны требовать ресурсов, нужных только при явном включении
  (журнал 2026-09-04: по умолчанию не создаётся лог-директория).
- Поверх env позже добавлены: «домашняя папка» `--root` с `adapter.env`
  (v0.9.11; явный env побеждает через `setdefault`) и `state.yaml`, который,
  наоборот, применяется поверх env для runtime-пула (ADR-025).

## Рассмотренные альтернативы

- Файл конфигурации как основной источник — частично принят только для
  структурированных данных (список бэкендов, тарифы), где env неудобен.

## Следствия

- Порядок приоритетов неоднороден и требует документирования:
  `state.yaml` > env > `adapter.env` дома > дефолт (для runtime-пула), но
  env > `adapter.env` > дефолт (для остального).
- Значения читаются на импорте модуля `config`, поэтому тесты перезагружают
  модуль (`importlib.reload`, фикстура `fresh_env`, ADR-030), а `--version` и
  `--help` разбираются до импорта `config` (ADR-028).
- Число переменных велико (десятки); против разрастания введены строгая
  валидация и `--check` (ADR-029).

## Доказательства

- `d1ad213`: `BACKEND_BASE = os.environ.get("ADAPTER_BACKEND_BASE", …)`.
- `CLAUDE.md`, «Принципы»: «Не ломать „нулевую настройку“…».
- Журнал ADR, запись 2026-09-04 (`docs/adr/archive/`).
- `backend_adapter/cli_args.py`, `backend_adapter/state_store.py`.

## Ответ автора (2026-10-10) — порядок приоритетов сознательный

- `state.yaml` перекрывает env, потому что он — **персистентность работы
  адаптера**: настройка, изменённая оператором в `/config`, должна пережить
  рестарт.
- Явный env перекрывает `adapter.env`, потому что env позволяет **запустить
  экземпляр с конфигурацией, отличной от базовой** (дом остаётся общим).

Итоговый порядок для переменных runtime-пула:
`state.yaml` > явный env > `adapter.env` дома > дефолт;
для остальных: явный env > `adapter.env` > дефолт.

**Замечание к последствию.** Две цели пересекаются на одном случае:
экземпляр, запущенный с явным env для переменной из runtime-пула, всё равно
получит значение из `state.yaml`, если общий дом уже содержит его. Если
нужны независимые экземпляры на общем доме, им требуется и свой
`ADAPTER_STATE` (переменная уже существует). Стоит одной строкой упомянуть
это в `docs/environment.md`.
