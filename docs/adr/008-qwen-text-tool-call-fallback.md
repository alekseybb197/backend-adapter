# ADR-008: Разбор текстовых вызовов инструментов Qwen как fallback

| Поле | Значение |
|---|---|
| Статус | Принято (MVP `d1ad213`) |
| Тип решения | deliberate (записано — проблема; реализация — по признакам) |
| Уверенность | high |
| Источник рационала | `README.md` «Проблемы» п. 4; changelog v0.3.0 (событие `tool_call_fallback`) |

## Контекст

Модели Qwen иногда возвращают вызов инструмента не в `tool_calls`, а текстом:
JSON внутри тегов `<tool_call>…</tool_call>`. Агент такой ответ воспринимает
как обычный текст, и агентный цикл обрывается.

## Решение

Если в ответе бэкенда есть текст, но нет `tool_calls`,
`parse_tool_calls_from_text()` пытается извлечь вызовы из текста и
превратить их в `tool_use`-блоки. Каждый такой случай пишется в trace
отдельным событием `tool_call_fallback` — как деградация, а не норма.

## Рассмотренные альтернативы

- Не исправлять, оставить модели. Отвергнуто: ломает агентный цикл.
- Отдельное событие было выделено из прежнего `harness_branch` в v0.3.0,
  чтобы не смешивать реальную деградацию модели с диагностикой самого
  адаптера.

## Следствия

- Эвристика может как пропустить вызов (иной формат тегов), так и создать
  ложный (тег в обычном тексте). Риск принят ради работоспособности цикла.
- Событие `tool_call_fallback` позволяет измерить, как часто модель
  деградирует.
- **Наблюдаемое ограничение:** fallback работает только в не-стриминговом
  ответе. `parse_tool_calls_from_text` вызывается единственный раз — из
  `convert_openai_to_anthropic`; в `streaming.py` вызовов нет. [CC] по
  умолчанию запрашивает стрим (`ADAPTER_STREAMING_ENABLE=1`), значит в
  основном режиме работы проблема №4 из README адаптером не закрывается.

## Доказательства

- `backend_adapter/convert.py`: `parse_tool_calls_from_text` (единственный
  вызов — внутри `convert_openai_to_anthropic`), эмиссия `tool_call_fallback`.
- `grep parse_tool_calls_from_text backend_adapter/streaming.py` — пусто.
- `docs/architecture.md` §5.2 «Text fallback» (описан только для non-stream).

## Открытые вопросы автору

- Отсутствие fallback в стриме — сознательное (нельзя ретроактивно
  превратить уже отправленные `text_delta` в `tool_use`) или пробел? Если
  сознательное — это ограничение стоит записать в README рядом с проблемой
  №4.
