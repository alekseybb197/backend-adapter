# ADR-005: Python 3.10+ и единственная внешняя зависимость — PyYAML

| Поле | Значение |
|---|---|
| Статус | Действует (2026-08-31, v0.6.9); дефект парсера **исправлен** в v1.0.1 (WIP) |
| Тип решения | deliberate (записано) |
| Уверенность | high |
| Источник рационала | журнал ADR, запись 2026-08-31 (оригинал — `docs/adr/archive/`) |

## Контекст

С появлением YAML-дампов сессий (`becdabd9`) `session_log.py` безусловно
импортировал `yaml`, но документация заявляла «только стандартная
библиотека», манифеста зависимостей не было, а аннотации `X | Y` уже
требовали Python ≥ 3.10 при заявленном 3.8+.

## Решение

- `requirements.txt`: `PyYAML>=6.0`; установка задокументирована.
- Официальный минимум — Python 3.10+.
- Ленивый импорт PyYAML **не** делается: зависимость безусловная.

## Рассмотренные альтернативы

- Ленивый импорт PyYAML, чтобы ядро прокси оставалось stdlib-only. Отвергнут
  (без записанной причины).

## Следствия

- Формулировку «только стандартная библиотека» можно применять к отдельным
  модулям, но не к проекту.
- **Побочный эффект (accidental):** парсер YAML бэкендов
  `config._parse_backend_yaml` остался самописным (введён в v0.5.0 именно
  «без зависимости от PyYAML»), хотя PyYAML с v0.6.9 доступен всегда. Парсер
  читает только `name`/`base`/`key` построчными регэкспами, тогда как
  `tariffs.yaml`, `state.yaml` и **проверка того же `adapter.yaml` в
  `--check`** используют PyYAML.

## Подтверждённое следствие: `--check` и рантайм читают `adapter.yaml` по-разному

Мини-парсер начинает новую запись только со строки `- name:`. Корректный
YAML, где первым ключом записи идёт не `name`, читается неверно:

```yaml
backend:
  - name: first
    base: https://a.example.com
    key: KEY_A
  - base: https://b.example.com   # запись начинается не с name
    name: second
    key: KEY_B
```

| Читатель | Результат |
|---|---|
| `--check` (`env_check._check_adapter_yaml`, PyYAML) | `[OK] … 2 запись(ей), поля name/base/key заполнены` |
| рантайм (`config._parse_backend_yaml`) | `[{'name': 'second', 'base': 'https://a.example.com', 'key': 'KEY_B'}]` |

Вторая запись «приклеивается» к первой: бэкенд `second` получает адрес
бэкенда `first`, **токен `KEY_B` отправляется на `a.example.com`**, бэкенд
`b.example.com` пропадает. Предупреждений нет. Воспроизведено на v1.0.0.

Исправление: читать `adapter.yaml` через `yaml.load(..., Loader=yaml.BaseLoader)`
и в рантайме (PyYAML уже обязательна), сохранив правило «прочие ключи
игнорируются». Выбран именно `BaseLoader`, а не `safe_load`: скаляры остаются
строками как написаны (`name: yes` → `"yes"`, `name: 0123` → `"0123"`), и
рантайм видит файл так же, как офлайн-режим `--check`.

## Доказательства

- `f675148` — `requirements.txt` и документация установки.
- `backend_adapter/config.py`: `def _parse_backend_yaml` (PyYAML `BaseLoader`).
- changelog v0.5.0: «самописный мини-парсер YAML — без зависимости от PyYAML».

## Ответ автора (2026-10-10)

Мини-парсер **не пересматривался** после появления PyYAML (тип —
`accidental`). Решение: переписать на PyYAML. Исправление — в коммите
`fix(config): adapter.yaml через PyYAML BaseLoader вместо регэксп-парсера`
той же ветки.
