# ADR-015: Fail-fast на старте и строгая проверка модели

| Поле | Значение |
|---|---|
| Статус | Принято (v0.3.3) |
| Тип решения | deliberate (записано) |
| Уверенность | high |
| Источник рационала | changelog v0.3.3 (восстановлен из `becdabd9:changelog.md`); `docs/architecture.md` §4.1 |

## Контекст

Агент может прислать имя модели, которой нет на бэкенде. Бэкенд может быть
недоступен при запуске.

## Решение

- На старте адаптер опрашивает `GET /v1/models` каждого бэкенда. Бэкенд,
  который не ответил, выпадает с `[WARN]`; **если не получено ни одной
  модели — адаптер не стартует** (`[FATAL]`, exit 1), «чтобы пользователь
  сразу увидел проблему».
- `GET /v1/models` адаптера отдаёт объединённый список.
- `ADAPTER_STRICT_MODELS=1` (дефолт): модель запроса вне списка → 400 со
  списком доступных моделей. `0` — пропускать любую модель.
- Поле `model` обязательно (v0.4.1 убрал хардкод модели по умолчанию).

## Рассмотренные альтернативы

- Ленивый опрос моделей при первом запросе — не выбран (мотив: заметить
  проблему сразу).

## Следствия

- Адаптер нельзя запустить заранее, до старта бэкенда (например, в
  docker-compose без зависимостей). Readiness-проба `/ready` (ADR-023)
  отражает то же условие.
- Список моделей кэшируется; новые модели бэкенда видны после проверки по
  кнопке или при первом заходе на `/` (без рестарта, v0.8.2).
