# ADR-030: Контроль качества — четыре обязательные проверки и тест реального процесса

| Поле | Значение |
|---|---|
| Статус | Действует (2026-09-01 — тесты; v0.7.1 — CI; v0.8.6 — интеграция; v0.9.3 — molecule) |
| Тип решения | deliberate (записано) |
| Уверенность | high |
| Источник рационала | журнал ADR 2026-09-01, 2026-09-08 (×2); `CLAUDE.md` «Проверка перед коммитом» |

## Контекст

К 2026-09-01: 11 модулей, ~2300 строк, ни одного теста, по 5 версий в день.
«Дальнейшие изменения (конвертация протоколов, стриминг, ретраи) ломались бы
незаметно».

## Решение

- **Перед каждым коммитом** — четыре команды, все зелёные:
  `ruff check`, `ruff format --check`, `mypy --strict`, `pytest`.
  CI повторяет тот же набор (v0.9.0).
- **Один файл тестов на модуль** (`tests/test_<module>.py`); тесты без сети,
  бэкендов и ключей.
- Изоляция: перезагрузка модулей (`fresh_env`, `importlib.reload`) — потому
  что конфигурация читается из env на импорте (ADR-004, ADR-017).
- Интеграция сервера — `fake_backend` (`ThreadingHTTPServer` на случайном
  порту).
- **Реальный процесс** — `tests/test_manual_check.py` (маркер `manual`):
  старт, WEBUI, логи, Cost, сигнальный контракт (ADR-026); входит в общий
  прогон (~30 с).
- `install.sh` — molecule-сценарии (Ubuntu 24.04), CI-джоб только при
  изменении `install.sh`/`molecule/` (path-гейты, v0.9.4).

## Следствия

- Масштаб: 32 файла, ~1100 тестовых функций; ~19 000 строк тестов против
  ~16 000 строк пакета.
- `mypy --strict` в CLI при не-strict конфиге `pyproject.toml` — две
  конфигурации типизации; строгая живёт только в команде.
- Тесты не проверяют инвариант DAG (ADR-016) и не покрывают `install.sh` на
  macOS.
