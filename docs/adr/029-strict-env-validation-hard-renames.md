# ADR-029: Строгая валидация конфигурации и жёсткие переименования

| Поле | Значение |
|---|---|
| Статус | Действует (v0.9.6 — валидация; v0.9.9 — политика переименований; v0.9.13 — `--check`) |
| Тип решения | deliberate (записано) |
| Уверенность | high |
| Источник рационала | changelog v0.9.6, v0.9.9, v0.9.10, v0.9.13; docstring `env_check.py` |

## Контекст

Десятки env-переменных (ADR-004). Опечатка в значении давала тихий
`ValueError` или противоположное поведение. Переменные часто
переименовывались.

## Решение

- **Типы env — строго, до импорта `config`:** невалидный int/bool →
  `[FATAL] <имя>=<знач>: ожидается <тип>`, `exit 1` (`env_validate.py`).
- **YAML — мягко:** битые записи `adapter.yaml`/`tariffs.yaml`/`state.yaml`
  пропускаются с `[WARN]` и причиной.
- **Значения перечислений — мягко:** неверный TARGET → `[WARN]` и `none`.
- **Переименования — жёсткие:** старое имя не читается, fallback нет;
  если оно задано — одна строка `[WARN]` с подсказкой; старт продолжается.
  Применено: `ADAPTER_DEBUG_LOGPATH` → `ADAPTER_DATA_ROOT`,
  `ADAPTER_DEBUG_PARTS` (удалён), `ADAPTER_DEBUG_TRIM` → `ADAPTER_LOG_TRIM`.
- **`--check`** (v0.9.13) — офлайн-диагностика дома: типы, устаревшие имена,
  структура YAML; exit 1 при `[ERROR]`. Предупреждения — только для
  известных устаревших имён и семейства `ADAPTER_DEBUG_*`; прочие
  `ADAPTER_*` молчат (это могут быть имена токенов бэкендов).

## Рассмотренные альтернативы

- Fallback со старого имени на новое. Отвергнут (по признакам: упрощение
  кода; явно не записано).

## Следствия

- Три уровня строгости (FATAL для типов, WARN+дефолт для enum и YAML,
  WARN+игнор для старых имён) — нужно знать, какой где.
- Пользователь со старым именем переменной получает **другое** поведение
  (дефолт), а не ошибку — например, логи пойдут в `~/.ba` вместо прежнего
  каталога.

## Доказательства

- `backend_adapter/env_validate.py` (`_ENV_SPECS`, `check_value`),
  `env_check.py` (`_LEGACY`, `parse_env_text`).
- `backend_adapter/config.py`: обработка снятого `ADAPTER_DEBUG_PARTS`.
- `3e4cef4`, `45251dc`, `de59582`, `0960e0b`, `7ae6152`.

## Ответ автора (2026-10-10) — `[WARN]` сознательно

1. Устаревшие имена **игнорируются** — значит, это не ошибка конфигурации,
   а лишняя строка.
2. Корректная конфигурация инжектируется при установке (`--install`,
   `install.sh`) — реализовано только в последний момент, поэтому старые
   окружения ещё встречаются.
3. **Толерантность к обновлению:** обновлённый бинарник не должен падать на
   старом env.

Решение подтверждено. Риск тихой смены каталога данных снижается тем, что
`[WARN]` печатается при каждом старте и `--check` его тоже показывает.
