# ADR-027: Тяжёлая отрисовка артефактов — в фоне с дебаунсом, вне пути запроса

| Поле | Значение |
|---|---|
| Статус | Действует (v0.9.10); инкрементальная сборка — v0.8.0 |
| Тип решения | deliberate (записано) |
| Уверенность | high |
| Источник рационала | changelog v0.9.10; журнал ADR 2026-09-04 (v0.8.0) |

## Контекст

Дерево артефактов сессии (разбор `*.parts`, PlantUML/Graphviz-рендер с
60-секундным таймаутом, интерактивный HTML) дорогое. Строить его в потоке
прокси-запроса нельзя (ADR-002: поток держит ответ агенту), а лениво при
заходе на `/session` — медленно на больших сессиях.

## Решение

- Запись части (`write_debug_json`) только **помечает** каталог сессии
  «грязным» (`artifact_refresh.notify`) — дёшево.
- Один поток-демон на процесс раз в секунду перерисовывает каталоги, после
  последней записи в которых прошёл тихий период `ADAPTER_ARTIFACT_DEBOUNCE`
  (20 с): серия частей одного хода — одна перерисовка.
- Отрисовка инкрементальная, от чекпойнта `.build_state.json` (v0.8.0);
  битый чекпойнт — холодный пересбор.
- Ленивая сборка при заходе на `/session` осталась страховкой (после
  рестарта).
- Ошибки пометки и рендера не роняют запись (канал наблюдательный).

## Рассмотренные альтернативы

- Синхронная сборка в пути запроса. Отвергнута.
- Только ленивая сборка при просмотре (до v0.9.10). Дополнена фоновой.

## Следствия

- Дерево отстаёт от реальности минимум на период дебаунса.
- Рендер идёт в том же процессе и делит GIL с прокси; внешние рендереры
  (PlantUML/Graphviz) — отдельные процессы.

## Доказательства

- `backend_adapter/artifact_refresh.py` (`notify`), `session_log.write_debug_json`,
  `artifact_tree.generate`.
- `72532e9`, `9722ae9`.
