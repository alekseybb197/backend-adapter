## Легенда

**Тип решения**

- `deliberate (записано)` — автор зафиксировал решение и мотив.
- `deliberate (по признакам)` — решение явно сознательное (принцип, повтор,
  защитный код), но мотив или альтернативы не записаны.
- `inferred` — гипотеза по косвенным признакам.
- `accidental` — признаки унаследованного, а не выбранного состояния.

**Уверенность** — `high` / `medium` / `low`: насколько надёжно восстановлено
содержание решения (не «насколько оно хорошее»).

Раздел «Открытые вопросы автору» в ADR — то, что из артефактов
восстановить нельзя. Ответ автора переводит решение в `deliberate (записано)`.

## Архитектурные драйверы (as-built)

Восстановлены из `CLAUDE.md` («Приоритеты») и повторяющихся решений:

1. **Совместимость** агентов на Anthropic API с бэкендом, который надёжно
   говорит только на Chat Completions.
2. **Надёжность** на критическом пути агента (ретраи, таймауты, стрим без
   разрывов протокола).
3. **Наблюдаемость** поведения агента и модели — от консоли до полного
   трейса с причинностью вызовов инструментов.
4. **Минимум зависимостей** и **нулевая настройка**.
5. **Безопасные дефолты** (localhost, маскирование секретов, флаги «выкл»).

## Как поддерживать

- Новое решение — новый файл `NNN-краткое-имя.md` по образцу; изменение
  решения — новый ADR со ссылкой «заменяет NNN», старый получает статус
  «Заменено».
- Критерий записи — из исходного правила журнала (`d72f1cb`): новый
  компонент/модуль, контракт протокола, ограничение зависимостей, каркас
  тестирования. Мелочи — только в changelog.
- Восстановленные ADR после ответа автора на открытые вопросы меняют тип на
  `deliberate (записано)`.
