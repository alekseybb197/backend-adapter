# ADR-017: Глобалы модуля `config` как разделяемое состояние процесса

| Поле | Значение |
|---|---|
| Статус | Действует (складывалось с v0.5.0; инвариант мутации выровнен в v0.9.8) |
| Тип решения | deliberate (по признакам) — компромиссы записаны, само решение нет |
| Уверенность | medium |
| Источник рационала | журнал ADR 2026-09-04, 2026-09-05; changelog v0.9.8; комментарии `config.py`; реконструкция |

## Контекст

В одном процессе работают потоки запросов (ADR-002), поток WEBUI, поток
экспортёра, фоновая проверка бэкендов и фоновая отрисовка артефактов. Всем
нужны список бэкендов, кэш моделей и runtime-настройки.

## Решение

- Состояние — глобалы модуля `config` (`_BACKENDS`, `_AVAILABLE_MODELS`,
  `_MODEL_TO_BACKEND`, `ADAPTER_*`). Нет объекта-контекста, нет
  dependency injection.
- Читается **через модуль** (`config.X`), а не `from config import X`:
  иначе значение копируется на импорте. Runtime-пул `/config` читается живьём
  (v0.8.0).
- **Коллекции мутируются на месте** (`clear()` + `extend()`/`update()`),
  **скаляры переприсваиваются** (инвариант v0.9.8).
- Синхронизация точечная: короткие локи вокруг мутации таблиц
  (`_TABLE_LOCK`, `_REFRESH_LOCK`); снимок состояния фоновой проверки
  неизменяем и заменяется целиком — читателям лок не нужен.
- `refresh_models` мутирует кэши моделей из фонового потока **без** общего
  лока — записанный компромисс («существующий компромисс чтения словарей при
  clear+update», журнал 2026-09-05).
- `backend_adapter/__init__.py` — ленивый прокси глобалов.

## Рассмотренные альтернативы

Не записаны. Очевидные: объект-контекст, передаваемый в обработчики;
иммутабельные снимки с атомарной заменой для всех кэшей.

## Следствия

- Просто и быстро в разработке, но с реальными дефектами по ходу истории:
  - v0.7.2 — `in-place mutation of model cache globals` (`ea78e12`);
  - v0.8.6 — баннер всегда показывал «0 backends»: точка входа держала
    копию списка, который `_init_multi_backends` переприсваивал (исправлено
    в v0.9.8 введением инварианта).
- Окно гонки: `refresh_models` обновляет кэши как `clear()` → `update()`.
  Запрос, попавший между ними, видит пустые словари. Strict-проверка в этом
  случае **пропускается** (условие `and _AVAILABLE_MODELS` в `server.py`), а
  поиск бэкенда в пустом `_MODEL_TO_BACKEND` уходит в фолбэк на дефолтный
  бэкенд. Итог: запрос к модели не-дефолтного бэкенда может быть отправлен не
  туда. Окно короткое, но открывается при каждой проверке по кнопке и при
  первом заходе на `/`.
- Тесты изолируют состояние перезагрузкой модулей (ADR-030).

## Доказательства

- `backend_adapter/config.py`: `_REFRESH_JOB`, `_REFRESH_LOCK`,
  `_refresh_worker` (комментарий о компромиссе), `reload_backend_config`;
  `_AVAILABLE_MODELS.clear()` / `.update(available)` в `_init_multi_backends`
  и `refresh_models`.
- `backend_adapter/server.py`: `from … import _AVAILABLE_MODELS` и
  strict-проверка `config.ADAPTER_STRICT_MODELS and _AVAILABLE_MODELS and …`.
- `backend_adapter/model_usage.py`: `_TABLE_LOCK`.
- changelog v0.9.8 «Информативный баннер бэкендов» — описание инварианта.

## Ответ автора (2026-10-10)

Окно гонки — новая информация; решение требуется. Предложение —
[ADR-033](033-proposal-atomic-model-index.md).
