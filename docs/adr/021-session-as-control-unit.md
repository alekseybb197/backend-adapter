# ADR-021: Сессия агента — единица управления; две модели наследования настроек

| Поле | Значение |
|---|---|
| Статус | Принято (v0.9.5); модели наследования — v0.9.8 (Log), v0.9.9 (TARGET) |
| Тип решения | deliberate (записано) |
| Уверенность | high |
| Источник рационала | changelog v0.9.2, v0.9.5, v0.9.8, v0.9.9; `docs/architecture.md` §6.10–6.11 |

## Контекст

Через один адаптер одновременно работают несколько агентов и сессий. Включать
подробные логи или менять маршрут для всех сразу неудобно: нужна одна
проблемная сессия.

## Решение

- **Идентификатор сессии** — первый непустой заголовок из списка
  `ADAPTER_SESSION_HEADER` (дефолт: `X-Claude-Code-Session-Id`,
  `x-opencode-session`, `x-codex-turn-metadata:session_id` — синтаксис
  `Имя:ключ` для JSON-заголовков). Нет ни одного — `unknown`.
- **Таблица сессий** (`/sessions`): строка — кортеж
  `(session, agent, model, backend, route)`; смена модели или маршрута — новая
  строка. Глубина — `ADAPTER_SESSIONS_TABLE` (10 строк, вытеснение старых).
- **Пер-сессионные переопределения** Log и трёх TARGET.
- **Две модели наследования — намеренно разные:**
  - **Log — снимок** общего флага при первой встрече сессии; дальше сессия
    живёт своим значением; общий флаг — лишь шаблон для **новых** сессий.
  - **TARGET — живое наследование**: «не задано» = текущее общее значение;
    выбор значения, равного общему, снимает переопределение.
- **Нет персистентности:** таблица сессий и переопределения (включая модель,
  выбранную `/model`, ADR-013) живут только в памяти процесса — «осознанное
  решение» (`docs/architecture.md` §6.10).

## История

| Версия | Было | Почему изменено |
|---|---|---|
| v0.9.5 | Log/Parts живо наследуют, есть состояние `inherit` | — |
| v0.9.8 | Log — снимок, `inherit` убран | глобальный тумблер включал сбор частей **всем** сессиям, а сессионный не включал ничего (гейт стоял снаружи) |
| v0.9.9 | TARGET без `inherit` (два состояния) | одна модель вместо трёх состояний |

## Рассмотренные альтернативы

- Глобальные настройки без сессий. Отвергнуто: нельзя отлаживать одну
  сессию среди многих.
- Единая модель наследования для всех полей. Отвергнута: Log — свойство
  записи сессии (нельзя «включить задним числом»), TARGET — политика
  маршрутизации, которую оператор меняет для всех.

## Следствия

- После рестарта адаптера переопределения теряются, а сессия агента
  продолжается — Log возвращается к шаблону, выбранная `/model` сбрасывается.
- Лимит таблицы считает строки-кортежи, а не сессии: одна сессия с частыми
  сменами модели может вытеснить остальные.
- Без заголовка сессии (неизвестный клиент) файловые логи невозможны
  вообще.
